## 4. 新环境暴露的缺陷（本地测试未覆盖）

| # | 现象 | 影响 | 处置 |
|-|-|-|-|
| N1 | **定向重跑 `questions --item-id` 覆盖了 `question_records.jsonl`**：只处理 1 篇时，汇总 jsonl 被写成只剩这 1 篇（状态库仍有 23 篇） | 正是 P4 要根治的"jsonl 落后于库"，只是换到出题阶段重现 | 已修：汇总 jsonl 改**合并写**（读旧 + 覆盖同 item_id + 写回），重跑后 23/23 一致 |
| N2 | **`audit` 检查点 2 在本地 ingest 链路上误判 FAIL**：断言"两个云盘源都已盘点"，但 `ingest --dir` 根本没有云盘盘点，源名是本地文件夹名 | 推荐的本地入口跑完 audit 直接 FAIL，会误导同事以为流程失败 | 已修：仅当存在 `source_inventory.jsonl`（跑过云盘 inventory）时才断言两源；本地链路改断言"条目均带来源名" |
| N3 | **`status` 的 `next_action` 未感知出题阶段**：做完 questions 仍建议 `collection.generate_queries` | 编排者照 next_action 走会空转/重复 | 已修：`_decide_next` 接收 queries/questions 计数，有 query 无题目→推荐 `generate_questions`，均有→`report` |
| N4 | 手工拼 `runtime.json` 的 Windows 路径得**非法 JSON**（`Invalid \escape`） | 首次部署时 agent 需知道要用 `json.dump` | 记为体验项：onboarding 生成 runtime.json 一律用 JSON 序列化，不字符串拼接 |
