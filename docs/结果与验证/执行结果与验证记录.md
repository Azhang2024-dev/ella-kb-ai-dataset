```powershell

.venv\Scripts\python scripts\collection_cli.py --help
```

## 3. 修掉的缺陷（共 22 个，全部有回归用例）

完整台账见 `docs\document_collection\开发日志.md` 第 3 节。
这里只列**会直接影响数据正确性**的几个：

| 编号 | 问题 | 为什么危险 |
|-|-|-|
| **D5** | `lark-cli.CMD` 经 cmd.exe 把分页 token 里的 `\|` 当管道 | 第 2 页起全部失败，但退出码是 0。**第一次盘点少了 1414 条（29%）且毫无报错** |
| **D16** | 语种识别把斯瓦希里语判成西班牙语、乌尔都语判成阿拉伯语、孟加拉语判成英语 | 范围外语种被当成 P0 语种收进最终集，直接污染语种配额 |
| **D2** | 采集阶段的硬拒绝（超限文件）在筛选阶段被软化成 needs_review | 等于放软了"大小上限是硬门槛"这条不可违反的约束 |
| **D12** | 分层抽样 80 条**全部**来自第二个源 | 违背计划"两个源各取 30 份"，样本失去代表性 |
| **D14** | screen 跑全量 4892 条，把 4812 条从未采集的塞进人工复核队列 | 复核队列完全不可用 |
| **D19** | 在线资源导出产物每次字节都不同 | 如果按 SHA-256 判"可复跑"，这条检查点永远红，真正的回归反被淹没 |
| **D20** | 内容寻址文件名 68 字符 + 深工作区 撞 Windows MAX_PATH | `WinError 3`，且文件其实已存在只是普通 API 看不见 |
| **D22** | 从未比对服务端声明字节数、落盘后也没复核哈希 | 下载截断会被当成完整文件入库 |

## 4. 真实数据的几个关键事实（都是实测，不是推测）

1. **飞书清单和元数据接口都不返回文件大小**（`drive files list` / `drive metas batch_query`）。
   所以大小门槛只能在下载后按本地字节数判定。
2. **`drive +download` / `+export` 的 `--output` 必须是相对当前工作目录的路径**，
   绝对路径会被直接拒绝。
3. **在线文档导出会返回 `code=600 hybrid resource expired`，它是可重试的**
   （同一份 docx 隔几秒重试即成功）。修复错误分类后，同样 80 条样本的
   `pending_export` 从 **19 条降到 1 条**。剩下那 1 条是 `code=1069902 no permission`，
   程序重试解决不了，需要业务方补授权。
4. **下载类产物逐字节可复现（60/60），导出类不可复现（0/10）**，
   字节数每次差几个 byte。跨运行去重必须依赖规范化正文指纹。
5. **授权 refresh token 2026-09-16 到期**，之后需要重新授权，否则采集会批量失败。

## 5. Pilot 结果与下一步

80 条均匀分层样本（两个源各 40）的结果：

```text
采集    acquired 70 / conversion_required 5 / rejected 4 / pending_export 1
抽取    70 / 70 成功
去重    重复 1 条，唯一 69 条
筛选    仅硬规则：accepted 29 / rejected 28 / needs_review 17 / 其他 6
        加语义复核：accepted 6 / rejected 41 / needs_review 27 / 其他 6
Query   6 份 x 10 条 = 60 条，全部通过 6 项校验
```

80 条样本里的语种分布（识别修复后）：

```text
en 10, pt 10, zh 9, ar 5, fr 5, id 5, tr 5, ru 4, es 3,
hi 3, sw 3, gu 2, ur 2, bn 1, ta 1, tl 1, unknown 1
```

**P0 六语种合计只有 36 / 80**，其余是范围外语种（`docQA.llm` 里有大量
swahili / hausa / tamil / gujarati / marathi / filipino / urdu / bengali /
indonesian / turkish / hindi 目录）。

所以要凑满 P0 的 120 份，**不能再做全源均匀抽样**，必须按语种目录定向采集：

```powershell
# 只盘 P0 语种目录
.venv\Scripts\python scripts\collection_cli.py --run-id p0 inventory --include-subfolder DOC-EN
# 或按来源+格式定向采集
.venv\Scripts\python scripts\collection_cli.py --run-id p0 acquire --source 知识库_2026 --extension pdf --limit 60
```

按 29/80 的硬规则合格率、6/29 的语义通过率推算，
要拿到 120 份最终合格文档，需要在 P0 语种目录里定向采集约 **1,600 份候选**；
如果只要过硬规则（语义复核另做），约 **350–400 份**。

其他遗留：

| 项 | 说明 |
|-|-|
| `pending_export` | 在线资源导出权限不足，需要业务方补授权后 `acquire --status pending_export` |
| `conversion_required` | 全量里有 17 个 `.doc` + 1 个 `.ppt`，需要批准转换器（本期不做） |
| 扫描 PDF | 本轮样本未命中，全量里预计有；需要 OCR 决策（本期不做） |
| P1 学科 | 只能由语义复核给出，未启用模型时报告如实显示"未判定" |
| 阿拉伯语版式双重核验 | 需求 6.2 要求，需要图文理解额度（每周每账号 3 次），本期未做 |
| 人工复核责任人 | `human_review_queue.csv` 需要指定谁来处理 |
