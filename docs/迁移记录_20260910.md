## 0. 为什么要迁

两周 MVP 的代码被写进了**另一个项目** `D:\Users\admin\Desktop\My_Project\Ella知识库数据集小工具`
（PySide6 GUI 爬虫工具）的仓库里，挂在 `feat/document-collection-mvp` 分支上；
而本任务的工作目录一直是 `D:\Users\admin\Desktop\My_Project\Ella知识库AI生题数据集`。

两个不相干的项目共用一个 git 仓库会带来三个实际问题：版本管理互相牵连、`.gitignore` 规则互相打架
（为了纳入 `scripts/collection_cli.py` 曾被迫改动原仓库的忽略规则）、交付时说不清"哪些文件属于这个项目"。
所以本次把本任务的全部产物迁出，成为独立仓库。

## 3. 绝对路径改写（迁移最大的风险点）

旧仓库根 `D:\...\Ella知识库数据集小工具` 被写死进了运行产物：`run_manifest.json` 的 `policy_path`、
`state.sqlite3` 的 `runs.workspace_dir` / `artifacts.path` / `extractions.text_path` / `decisions.evidence_json`、
`artifacts_meta/*.json`、各 `*.log`。不改写，历史 run 会全部指向已被清空的旧目录。

| 对象 | 数量 | 做法 |
|-|-|-|
| 文本文件（json/jsonl/csv/md/log/txt/xml/py） | **501 个文件 / 3,204 处** | 同时替换单反斜杠形式与 JSON 转义形式（`D:\\\\...`） |
| `state.sqlite3` | **7 个库 / 1,531 行** | 按列执行 `UPDATE ... SET col = REPLACE(col, 旧, 新)`。**不做二进制替换**：新旧根长度不同（13 → 14 字符），直接改字节会破坏 SQLite 页结构 |
| 文档引用 | 3 份文档 / 7 组 | `document_collection_scope.md` 第 1 节改写为"当前基线 + 迁移前基线（历史记录）"；开发日志的计划来源路径与迁移说明；`执行结果与验证记录.md` 里 10 处 `Ella知识库数据集小工具\` 前缀改为本仓库相对路径 |

改写后全库扫描 `Ella知识库数据集小工具` 完整路径残留 = **0**。
